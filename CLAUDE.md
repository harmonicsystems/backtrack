# BackTrack

A quiet backing track for drum and singing practice. Display name is **BackTrack** (reads as *backing track*; matches Harmonic**Systems** / Tide**Breath**); the URL path, repo, `localStorage` keys and cache names stay lowercase `backtrack`. Roadmap: `~/.claude/plans/yes-fix-both-bugs-snoopy-lecun.md` (modules → recording → Breathe mode → pitch → tempo tools). Sibling of Tide Breath (`~/Code/breathe`): same design tokens, night mode and service worker. No framework, no build, no backend: `index.html` (markup + CSS) loads native ES modules:

- **Main screen** is only the circle, one quiet guide line (a button that opens Setup) and the thumb row: **● Rec · Setup · Takes n**. While playing, everything but Rec dims. While playing, the nav and thumb row dim.
- **Setup sheet**: a *non-modal* `<dialog id="sheet">` opened with `.show()` inside `#app` — `showModal()` would put it in the top layer and escape the turned (rotated) `#app`. While open, `nav` and `main` are `inert`; Esc, the scrim, **Done**, or dragging the header down (> 90 px or a quick flick) close it. Turned on an upright phone, "down" is the finger moving left, handled in `initSheet()` via `turned()`. **Setup opens on the glance list** (2026-09-30, from the Design canvas mockups): one row per section — Groove · Click · Drone · Practice · View · Save in Groove, Pattern · Sound · View · Save in Breathe, Key · Lines · Sound · Save in Tune — each with an icon and its current values drawn small (`renderGlance()` in ui.js: a filled bar for a level, a dot on the seven-groove scale, one bar of click-pattern dots, drop-out as filled/hollow squares, the number as a caption under its own picture), plus a **Recents** row: the last three distinct setups *played* (sessions ≥ 20 s now log `preset`, `home`, `icon`; older entries without them never show), newest first, the current one left out; a tile loads that preset, mode included (`loadPreset()` in app.js, the `hashchange` path). Tapping a row shows that section's panel with **‹ Setup** in the header (`selectTab(name)`; `'list'` is the list; rows carry `data-modes` as the tabs did, `syncTabs()` hides the other modes' rows and drops back to the list if the open panel isn't in the mode). There is no tab row and no remembered tab: Setup always opens on the list. **One height**: the list and every Setup panel share one grid cell (inactive ones `.behind`: invisible + inert), so the sheet is always the tallest panel's height (454 px on a 375-wide phone; keep new panels ≤ 371 px of content; the list is 346 with seven rows); each panel scrolls itself when the sheet is clamped. Save holds the shortcut card, the session stats and the link.
- **Recording (Phase 2, 2026-09-25).**
  - The mic is open **only while ● is on** (`openMic` → capture → `endCapture` stops the tracks). Voice processing is off (`echoCancellation/noiseSuppression/autoGainControl:false`). `navigator.audioSession` is `play-and-record` only while open; `setRouting(true)` stops the route change from counting as an outside pause. First ● tap shows the `mic` sheet explainer before the iOS prompt (`backtrack-mic` remembers it).
  - Capture is an **AudioWorklet**, not MediaRecorder: each chunk carries `currentFrame`, so every sample's position on the ctx clock is exact. Takes are 16-bit mono in IndexedDB `backtrack` (`takes` = metadata, `pcm` = audio, so the list never loads audio). 10-minute cap.
  - A take stores `barIndex` (first bar line at/after the mic opened; 0 when ● started the groove, count-in included as pickup), `alignSec` (seconds from the first sample to that bar), `latency` (round trip at record time), `nudge` (ms, + = your part later), and the groove settings. **A take has exactly one setup**: tempo/loop/count-in/fine/key/drone/drop-out/click changes end the take first (`endTake`); volumes don't. `stop()` saves a take in progress; an outside pause just freezes the capture with the clock.
  - `renderTake()` rebuilds the backing offline (drums from the right loop position with the take's drop-outs, click, count-in, crossfaded drone) and starts the mic `latency − nudge` seconds in, which puts the performance back on the backing's own timeline. Used for in-app playback and WAV export (peak-limited to −0.2 dB).
  - **Latency**: estimate = `baseLatency + outputLatency + 12 ms` until measured; **Measure** (speaker, quiet room) plays 8 clicks, finds them in the mic, stores the median in `backtrack-latency`. Verified with a fake mic (output delayed 80 ms): measured 101 ms (the stream path adds ~21 ms), and a mid-loop take then aligned within ~3 ms. **Measure finds delays up to 3 s** (2026-10-01, for a cast tab or AirPlay): the first click heard sets the delay (nothing sounds before it, so a long delay can't alias to the delay mod 0.5 s, as it did with a half-second window after each click), each click is then timed in a window around it, and if the last click isn't there the first was lost (a speaker waking up), so it steps back half a second. Fake mic: 0.08 / 0.8 / 2.2 s measured 101 / 821 / 2221 ms; the same with the first click muted; refused with four muted (heard 4).
  - **Sharing on iOS** needs the share sheet to open straight from a tap, so expanding a take prepares its WAVs first; Share buttons enable when ready (`relabel()` keeps them right across redraws). The mic file is mono and built straight from the stored Int16 samples (`micWav`, instant); the mix is one render (`renderMix`, stereo, written in one-second parts). Heavy renders are serialized (`serial()`), and nothing prepares while a take is recording. Chrome refuses to share more than 50 MiB, so larger files (non-iOS) download instead.
  - **One capture at a time** (`openMic()` returns a handle that owns its stream/nodes/chunks; `micBusy()`): Rec is refused while Measure listens and vice versa. getUserMedia is started inside the tap and in parallel with loading the worklet; any failure stops the stream (no orange dot left behind). Stopping while "Opening mic…" closes the mic and starts nothing.
  - **An outside pause (call, lock screen) saves the take in progress** (`hold()` → `recStop()`): iOS may end a paused background app, taking unsaved audio with it. Resuming continues the groove without recording.
  - **IndexedDB**: iOS drops connections after time in the background, so `withDb()` reopens and retries once; if saving still fails, the take stays in memory and the toast offers "Share it" (mic WAV, no render needed).
  - **Takes are per home-screen app** (iOS gives each shortcut its own storage; removing a shortcut removes its takes). The mic explainer and the Takes sheet say so.
  - **Alignment verified (2026-09-25)**: feeding the recorder the app's own output through an exact 80 ms delay with latency set to 80 ms gives **0.00 ms** offset against the rebuilt backing (from stopped and mid-loop); through a media-stream fake mic after Measure, within ±1 ms. Test method that works: render the backing alone by passing a silent PCM to `renderMix`, then correlate it with `micBuffer`. (Subtracting a fitted mic from the mix does *not* work when the fake mic is a copy of the drums.)
  - **Testing gotcha**: the desktop preview pane, when hidden, sends Media Session "pause" to playing pages; the Chrome fallback handler then holds the session. Disable it in test scripts with `navigator.mediaSession.setActionHandler('pause', null)`.
  - **To verify on device**: whether opening the mic on AirPods drops playback to call quality; what Safari reports for `outputLatency`; mic/context sample-rate mismatch.
- **Breathe mode (Phase 3).** Groove | Breathe switch above the circle (idle only; dimmed while running). Tide Breath's pacer, but on the audio clock like the drums:
  - `scheduleBreath(T, spec, a, b)` puts swell curves (`setValueCurveAtTime`, eased like the circle, ending 2 ms early so curves never touch), cue tones (octave in · fifth hold · root out; `count` adds soft ticks each second) and the hum (a few partials per exhale) between times a and b. `breathStart()` keeps ≥ max(8 s, 2 cycles) scheduled on cycle boundaries (500 ms timer) with per-session cue/hum buses; an outside pause freezes all of it with the clock. `breathStart` glides the swell from wherever it is down to resting low by `t0 = now + .3` (a mid-inhale restart doesn't jump). Swell: `lowOf(s)` = gain `1 − .75s`, lowpass `6000·(350/6000)^s` Hz; top = 1 / 6000 Hz. Groove mode calls `flatSwell()` (20 kHz, gain 1). **Cancel-and-glide always goes through `settle()`** (audio.js): its `setTargetAtTime` starts one sample after `cancelAndHoldAtTime(now)`, because a curve cut there can end a hair past `now` and an event inside a curve throws (5 of 200 stops in the first inhale did, leaving the Wash playing). The live scheduler starts each chunk at `max(through, now + .02)` inside try/catch, so a stalled timer can't wedge it.
  - Drone choice `bsound`: `wash` (through the swell) · `hum` (scheduled per exhale) · `off`. `washWanted()` decides what the drone does in either mode. Breathe controls end a take and `restart()` like the groove's.
  - Transport dispatches on `runMode` (the mode the session started in), not `S.mode`, so a `#link` to the other mode mid-session stops the right engine. `tick()` → `where()` → `face.breath(w)`: the pulse/`#tfill` scale `.55 + .45·h`, phase word, seconds left, cycles done, the lit curve (`drawCurve`/`lightCurve`, from Tide Breath). Horizontal/night: `.tidebig`, one big tide circle instead of four beats.
  - **Breath takes**: `sess = { mode:'breathe', live, t0 }`, `alignSec = t0 − first captured frame` (negative when ● came mid-session); the take carries pattern/bsound/bcue/swell; `breathBacking()` runs the same `scheduleBreath` offline with `t0 = alignSec`. Verified with a Hum take: offline guide vs recorded live output within 0.02 ms (after the fake mic's own ~21 ms path delay, measured with a timed click). The Wash in a rendered breath take always starts at the top of its loop — not phase-locked to the live loop, which is fine for a drone.
  - **History** (IndexedDB v2 store `sessions`): one entry per start→stop of ≥ 20 s, paused time excluded, settings restarts don't split it; named by the last settings. Written (same id) at every outside pause and on `pagehide` too, then rewritten at stop — iOS may end a paused app. The Takes sheet shows the last 7 days per mode with the most-used pattern/groove ("Breathing 12 min · mostly Coherent breath"). Clear takes two taps. No streaks, no goals.
  - Presets: `?p=b-4-7-8-0-C` (in·hold·out·hold seconds, 0–30 in half seconds, not all zero) plus tokens `h` hum / `n` no drone, `k` count / `q` no cues, `s45` swell. `save()` keeps the last preset per mode; `switchMode()` restores it but keeps the key. Home-screen names use `breathHome()` ("4·7·8 breath"); icons `icons/b/{box,478,coherent,exhale,custom}.png` from `python3 tools/make-breath-icons.py` (one breath cycle drawn as the guide curve).
  - **Testing gotcha**: the in-app browser pane is shared with David — taps there (mode switch, circle) can land mid-test (the likeliest cause of an unexplained mode flip once). Re-check `S.mode` at the start of each scripted test.
- **Tune mode (Phase 4).** Groove | Breathe | Tune. The mic listens while the circle runs and your pitch draws as a line over the key's guide lines.
  - **Signal path**: the shared mic source → 4 kHz lowpass (sharper NSDF peaks for bright tones) → `AnalyserNode(2048)` → zero-gain sink; `tick()` reads it once per frame on the main thread (never in the worklet: a heavy step on the render thread would click the drone). `tracker.push(buf, sr, ctx.currentTime, {a4, droneHz})` ignores frames where the audio clock didn't move (a suspended context repeats its last buffer). `read()` gives `line` (trace, light smoothing), `midi`/`note`/`cents` (readout), `held`, `level`.
  - **Pitch is midi on the A4 grid**; `a4` (440/442/432) retunes the Wash (`washRate()` = playbackRate a4/440, crossfade timing uses duration/rate; offline takes store `washRate`), so the drone's root is always a whole note on the lines. Since 2026-10-01 the tuning is the phone's own setting for every mode (see **Tuning** below), not part of a Tune preset. Instruments (Concert/B♭/E♭/F = +0/+2/+9/+7 semitones) change only names: the drone stays concert; `writtenKey()`, `noteName()`.
  - **Measured (fake mic, Chromium)**: A2…E6 within ±1¢ (C3 +23 read 23, D5 −12 read −12 after the text smoothing), B♭-instrument concert B♭4 reads C, silence clears to "Listening" in ~2 s, the app's own Wash leaked into the mic at full level for 15 s drew no notes. Pipeline at a simulated 60 fps: notes lock within 1–2 frames, 0.01¢. The detector (agent-built) was tested against the real Wash/drum files; see its notes.
  - **Circle**: word ROOT/FIFTH/OCTAVE (or the scale degree), the written note, "8¢ above"/"on the line" (whole cents from a τ 250 ms average, 1.2¢ hysteresis, ≤ 5 text updates/s; Cents can be hidden). The disc scales with input level only ("I can hear you"); nothing is ever red/green or "sharp/flat". Horizontal/night running: the full-screen trace (`.tunebig`).
  - **Presets**: `?p=t-A` plus `iBb|iEb|iF`, `n` (no drone), `g72` (drums at 72 — Tune's drums pass their own groove settings to `grooveStart(isCurrent, g)`: 16 bars, no count-in/drop-outs/click), `lr|lmaj|lmin`, `r1|r2|r3` (lines low/middle/high; default follows your voice). Speed and Cents are per-device. Home-screen name `Tune in A` / `B♭ Tune in C`; icons `icons/t/{concertKey}[-Bb|-Eb|-F].png` from `tools/make-tune-icons.py`.
  - **The floor (pitch.js)**: learned from what the mic hears with nobody singing (room + drone/drum leak); falls at once, rises ≤ 1 dB/s while the gate is shut (20 dB/s for 2 s after `reset()`/`relearn()`), but **never more than 1 dB above the quietest half-second of the last 10 s** — a soft start used to raise the floor under the singer and lock them out until a pause (scratchpad test t6: 50% → 100%). Pitches below the drone's root need 18 dB (the phone's volume buttons can raise the leak without a relearn). Digital-silence frames never seed it. `relearn()` runs when the Wash is actually playing (`relearnAfter(washStart(...))`), on drums, volume and route changes.
  - **An outside pause (call, lock screen) stops Tune** instead of holding it: the mic (and AirPods' call mode) mustn't stay on while paused, and there's nothing to resume into. A take in progress is saved first.
  - **The mic is shared** (`rec.js`): one stream, opened while anything holds a lease (`openMic()` → lease, `releaseMic()`); each capture hangs its own worklet tap on the shared source. `openMic({ capture:false })` (Tune, Find mics) doesn't need the worklet; `wake:false` (Find mics) doesn't resume a stopped/paused context. If the worklet fails mid-open, the stream is dropped once it arrives. `endCapture()` returns `{ pcm, start, input, routeChanged }` (reroutes counted per take). ● Rec while Tune listens reuses the stream (no second prompt); a settings restart keeps Tune's lease; `stop()` releases it. Measure needs the mic to itself (`openMic({measure:true})`). The one-time explainer (`micSheet(forTune)`) has Rec and Tune wordings; its button calls `start(false, true)` (`explained`) so it can't loop back to itself.
  - **Mic choice** (Takes sheet and Tune ▸ Sound, `.micsel`): **the built-in mic by default** (David, 2026-09-25: on Automatic, AirPods took the mic for Tune and Groove takes and dropped to call quality). `micPick()` = `null` (built-in, default) | `'auto'` | `{id,label}`. The built-in's id is found once — the first open is Automatic, then `preferBuiltin()` names the inputs, picks the built-in (`findBuiltin`: "iPhone Microphone"/"(Built-in)", else the first non-headset input) and reopens with it — and kept in `backtrack-mic-builtin`, so later opens go straight to it. A `.micnow` line shows "Listening with: …" / "Last used: …". Named inputs use `deviceId:{exact}` (WebKit then calls `setPreferredInput`). Names exist only after the mic has been on in this page load, so "Find mics" opens it for a moment. Saved `{id,label}` in `backtrack-mic-pick`; a missing id falls back to Automatic (any failure → one retry without deviceId; a real denial fails again without a prompt); same label with a new id is re-saved. Latency is stored per input label (`backtrack-latency-by-input`; the old single value still applies to unmeasured inputs). Takes record `input` and `routeChanged`.
  - **WebKit facts (research 2026-09-25, from source)**: capture forces PlayAndRecord + VideoChat mode with HFP+A2DP allowed and DefaultToSpeaker. With AirPods and Automatic, iOS picks the AirPods mic (call quality both ways). Choosing the iPhone mic most likely moves playback to the **iPhone speaker** while the mic is on (bug 282939, Apple forum 741513) — not full-quality AirPods. A page can't drop HFP. Labels: any name containing "AirPods" becomes exactly "AirPods". `applyConstraints` can't switch mics. The reroute can land after getUserMedia resolves, so `setRouting(false)` waits 1.2 s. **Verify on device**: where the backing plays with each choice; whether takes really come from the chosen mic.
- **Metronome, meter, ramp, session length, the beats view (Phase 5, 2026-09-25).** The groove's timeline is one pure module (`js/timeline.js`): the live scheduler, the frame loop, `finishTake` and the offline render all ask it "when is bar b, cell i?" and "where am I at second s?", so sound, screen and a take's rebuilt backing can't drift apart. Verified in the in-app browser (bus tapped through the rec worklet): 7/8 eighths, 4/4 sixteenths and a drums+eighths ramp all land within 0.2 ms of the timeline; a click-only 7/8 take with a ramp renders 0.7 ms from the mic through the 80 ms fake mic after Measure.
  - **Sound: Drums | Click** (`S.sound`, Groove tab). Click = the click alone at any tempo 40–240 (a second slider, −/+ and **Tap tempo**: the median of the last 7 intervals after 4 taps, a 2 s gap starts over; touch taps on pointerdown, keyboard and VoiceOver with Enter/Space; −/+ and Tap share one timer, so the groove restarts once, 2 s after the last tap, and `pickTempo` skips a restart when the running groove already has the tempo); no drum file loads, no Fine (the bpm is exact), drop-out bars are silent, count-in / drone / takes / history as before. Click with the pattern **Off** is a silent visual metronome. `grooveStart(isCurrent, g)` builds `setupOf(g)` **after** the loop has loaded (a pattern changed while it loaded counts; Tune's drums still pass their plain settings object); `rescheduleFromNextBar` keeps the session's map (tempo, Fine, ramp, meter, bars from `clock.tl.setup`) and takes only pattern, grouping and drop-out from `S`, so a tapped tempo still pending can't move the clicks. A take's groove fields come from `sess.tl.setup` (what was heard), not the snapshot.
  - **Meter** (`S.meter` top 2–7 + `S.group`, click only; the loops are 4/4): a bar is `top` uniform **pulses** (the quarter in x/4, the eighth in x/8); **beats** are what you feel: every pulse in x/4 (5/4 = five beats, the grouping only places accents), each group in x/8 (6/8 = two beats of three, 7/8 = three uneven beats 2·2·3 / 3·2·2 / 2·3·2). **The bpm is the felt beat**: ♩ in x/4, ♩. in 6/8, ♩ in 7/8 (`unit` = 1 / 3 / 2 pulses per bpm beat; the readout shows the note and the meter hint the ♪ rate), so 96 stays "96 felt beats" across meters instead of collapsing to ♪ = 96. `pulseLevel`: 3 on bar and group starts, 2 on other beats, 1 inside a beat.
  - **The click pattern is one bar of cells** (pulses × sub; sub ≤ 4 in x/4, ≤ 2 in x/8 so no cell is shorter than the 60 ms click), each 0 off · 1 quiet subdivision · 2 beat · 3 accent. `S.click` codes: `1` Quarters/Beats, `2` Eighths, `3` Triplets, `4` Sixteenths, `b` Backbeat (2 and 4; 2/4 and 4/4 only), `o` Off-beats, `c` Custom (`S.cells` digits + `S.csub`; the Click tab's grid cycles a cell off → on → accent, updated in place so focus stays on the cell; entering Custom seeds it from the pattern showing). The pattern is a `<select>` (`#cpat`, labels per meter; Backbeat only in 2/4 and 4/4) so a Custom grid still fits the sheet. `cellsOf()` is the single expansion. **Levels** × `bus.click.gain` (= device-only `S.cvol`): over drums `[0,.06,.12,.12]` (the default is exactly the old .12 click), click-only `[0,.14,.3,.3]`, count-in `[0,.2,.35,.35]`; accent = 1600 Hz, the rest 1100. Old takes with `click:'on'` render as quarters at .12 through `setupOf`'s defaults.
  - **Tempo ramp** `S.ramp = 'step-every-cap'` (`r2.8.140` in a link, negative steps parse): +step bpm every N bars until the cap (the last step smaller when the cap falls inside one); bars count from bar 0 like drop-outs. On the click exact; on drums it steps `playbackRate` **at the map's bar lines** (k-rate, so the loop's position stays locked to the timeline) within `rate ∈ [.92, 1.08]` including Fine. - **Noise mode (2026-10-01, David: "a white noise generator feature with savable settings … customizable EQs, presets (brown, pink, etc)").** A fourth mode (Groove · Breathe · Tune · **Noise** on the mode switch); later its generator becomes a layer in Groove and Breathe.
